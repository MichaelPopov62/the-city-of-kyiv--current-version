# The City of Kyiv (лендинг)

Статичний сайт на **Vite** з формою зворотного звʼязку: фронт відправляє запит на невеликий **Express**-сервер, який пересилає текст у **Telegram**.

## Локальний запуск

1. `npm install`
2. Створіть `server/.env` за зразком `server/.env.example` (`TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`, за бажанням `CORS_ORIGIN`).
3. У режимі `npm run dev` запити форми йдуть на **внутрішній проксі Vite** (`…/api/send-question` → `127.0.0.1:9000/send-question`). Якщо бекенд на іншому порту: `SERVER_PORT=9001 npm run dev` і той самий `PORT` у `server/.env`. Якщо в кореневому `.env` задано **`VITE_API_URL`**, форма ходить напряму на цей URL (повний адрес з `http://`).
4. У двох терміналах:
   - `npm run server` — API на порту **9000** (або `PORT` у `server/.env`).
   - `npm run dev` — фронт на **5173**.

Форма шле `POST` на `{API_URL}/send-question` (локально — зазвичай `http://localhost:9000`, у продакшені — значення з секрету `VITE_API_URL` при збірці).

## Продакшен (GitHub Pages + окремий API)

- Статика збирається workflow `.github/workflows/deploy.yml` і потрапляє в гілку `gh-pages`.
- У репозиторії відкрийте **Settings** → **Secrets and variables** → **Actions**. На сторінці буде блок **Repository secrets** — натисніть **New repository secret**, ім’я **`VITE_API_URL`**, значення — повний URL бекенда (наприклад `https://api.example.com`), **без** завершального слеша.  
  *(Окрема вкладка «Variables» є не в усіх акаунтах/інтерфейсах; секрети підходять і для URL — значення просто приховане в логах.)*
- На сервері для продакшену бажано задати `CORS_ORIGIN` (origin сторінки на GitHub Pages). Якщо змінну не задано, сервер дозволяє будь-який origin (зручно для локальної розробки).

Прапорець `--base` у `package.json` (`build`) має збігатися з назвою репозиторію для коректних шляхів на GitHub Pages.

## Структура (фронт)

- Розмітка: `src/partials`, підключення в HTML через плагін інʼєкції.
- Стилі: `src/css`.
- Зображення: `src/img`.

У каталозі `React/` лежать окремі навчальні проєкти, до збірки лендингу вони не підключені.

### Підготовка до роботи

1. Переконайся, що на комп'ютері встановлено LTS-версію Node.js.
2. Встанови залежності: `npm install`.
3. Режим розробки: `npm run dev` → [http://localhost:5173](http://localhost:5173).

### Деплой на GitHub Pages

У `package.json` команда `build` містить `--base=/<REPO>/` — заміни на назву свого репозиторію, якщо потрібно.

У налаштуваннях репозиторію (`Settings` → `Pages`) джерелом має бути гілка `gh-pages`, папка `/` (root).

Детальні кроки зі скріншотами див. у історії комітів шаблону або в документації курсу.
